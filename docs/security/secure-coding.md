# 시큐어 코딩 규칙

코드를 작성하기 전에 읽는다. AI 도구로 코드를 만들 때도 같은 규칙을 적용한다 ([CLAUDE.md](../../CLAUDE.md)가 이 문서를 가리킨다).

각 항목의 괄호는 관련 OWASP Top 10 2021 / CWE 번호다. S4에서 다른 팀이 이 목록을 기준으로 공격한다.

## 1. 인가 (A01 Broken Access Control)

이 프로젝트에서 가장 흔하게 나올 취약점이다.

- **모든 API에서 서버가 권한을 검사한다.** 프론트엔드에서 버튼을 숨기는 것은 권한 검사가 아니다.
- **리소스 소유자를 확인한다.** `PUT /posts/{id}`는 "로그인했는가"가 아니라 "이 글의 작성자이거나 관리자인가"를 본다. (CWE-639, IDOR)
- 사용자 ID는 요청 본문·쿼리가 아니라 **인증 토큰에서** 꺼낸다.
- 역할(role)·상태(status)·작성자 같은 필드를 요청 DTO로 받지 않는다. 받는 필드를 화이트리스트로 정한다. (CWE-915, Mass Assignment)
- 기본값은 거부다. 공개 API는 명시적으로 열어 준다.
- 관리자 기능은 역할 검사와 함께 **누가 무엇을 했는지 로그**를 남긴다.

## 2. 인증과 세션 (A07)

- 비밀번호는 bcrypt·argon2 등 느린 해시로 저장한다. MD5·SHA-1·SHA-256 단독 사용 금지. (CWE-916)
- JWT 서명 키는 충분히 긴 무작위 값으로 만들고 GitHub Secrets / 파라미터 스토어에서 주입한다. `alg: none`을 허용하지 않고, 검증 시 알고리즘을 고정한다. (CWE-347)
- 액세스 토큰은 짧게, 리프레시 토큰은 회전(rotation)하고 로그아웃 시 무효화한다.
- 로그인 실패 메시지로 계정 존재 여부를 알려 주지 않는다. 로그인·가입에는 요청 횟수 제한을 둔다. (CWE-307)
- OAuth2는 `state` 파라미터를 검증하고, 리다이렉트 URI는 허용 목록으로만 받는다. (CWE-601)
- 토큰을 쿠키에 둘 때는 `HttpOnly`, `Secure`, `SameSite`를 설정한다.

## 3. 인젝션 (A03)

- SQL은 파라미터 바인딩(Prepared Statement, ORM)만 쓴다. 문자열 연결로 쿼리를 만들지 않는다. 정렬 컬럼처럼 바인딩이 안 되는 값은 화이트리스트로 검사한다. (CWE-89)
- 셸 명령을 사용자 입력으로 조립하지 않는다. (CWE-78)
- 사용자 입력을 경로에 쓰지 않는다. 필요하면 서버가 만든 ID로 매핑한다. (CWE-22)

## 4. XSS (A03)

- 게시글·댓글은 **출력할 때 이스케이프**한다. 프레임워크의 기본 이스케이프를 끄는 API(`innerHTML`, `dangerouslySetInnerHTML`, `v-html`, `|safe`)를 쓰지 않는다. (CWE-79)
- 서식 있는 글(HTML·마크다운)이 필요하면 검증된 새니타이저(DOMPurify 등)를 거친다. 직접 정규식으로 태그를 거르지 않는다.
- 응답에 `Content-Security-Policy`를 설정한다 (2R에서 DAST로 확인).

## 5. 파일 업로드 (갤러리·첨부파일)

- 파일 바이트는 서버가 받지 않고 **presigned URL**로 S3에 직접 올린다.
- presigned URL은 짧은 만료 시간, 고정된 `Content-Type`, 최대 크기 조건을 건다.
- 객체 키는 서버가 만든다 (예: `uploads/{uuid}`). 사용자가 준 파일명을 키로 쓰지 않는다. (CWE-22)
- 확장자뿐 아니라 MIME·매직 바이트로 형식을 확인한다. SVG·HTML은 이미지로 받지 않는다. (CWE-434)
- 다운로드는 `Content-Disposition: attachment`로 내려 브라우저가 실행하지 않게 한다.
- S3 버킷은 퍼블릭 접근을 차단한다.

## 6. 시크릿 (A02, A05)

- 시크릿은 코드·설정 파일·테스트·로그·커밋 메시지에 넣지 않는다. **GitHub Secrets**(CI)와 AWS 파라미터 스토어(런타임)에만 둔다.
- `.env`는 커밋하지 않는다. 필요한 변수 이름은 `.env.example`에 값 없이 적는다.
- 시크릿을 실수로 푸시했다면 커밋을 지우는 것으로 끝나지 않는다. **즉시 키를 폐기·재발급**하고 PL에게 알린다.
- AI 도구에 시크릿·`.env`·AWS 키를 붙여 넣지 않는다.

## 7. 에러 처리와 로그 (A09)

- 사용자 응답에 스택 트레이스·SQL·내부 경로를 노출하지 않는다 ([API 규약 3절](../conventions/api.md#3-에러-응답)). (CWE-209)
- 비밀번호, 토큰, 개인정보를 로그에 남기지 않는다. (CWE-532)
- 인증 실패, 권한 거부, 관리자 작업은 로그로 남긴다 (2R CloudWatch 모니터링 대상).

## 8. 의존성 (A06)

- 새 패키지는 이름·다운로드 수·유지보수 상태를 확인하고 추가한다. AI가 제안한 패키지는 실제로 존재하는지 확인한다.
- 잠금 파일(`package-lock.json`, `gradle.lockfile`, `poetry.lock` 등)을 커밋한다.
- Dependabot 보안 PR은 미루지 않는다.

## 9. 인프라 (A05)

- AWS 변경은 Terraform PR로만 한다. 콘솔 직접 수정 금지.
- GitHub Actions의 AWS 접근은 OIDC만 쓴다. 액세스 키를 발급하지 않는다.
- IAM은 최소 권한으로 준다. `"Action": "*"`, `"Resource": "*"`를 쓰지 않는다.
- 보안 그룹에서 `0.0.0.0/0` 인바운드는 로드밸런서 80/443만 허용한다.
- 스토리지·DB는 암호화하고 퍼블릭 접근을 막는다. Checkov 결과로 확인한다.

## 10. CI/CD (GitHub Actions)

- `pull_request_target`을 쓰지 않는다.
- `run:`에 `${{ github.event.* }}` 값을 직접 넣지 않고 `env:`로 넘긴다 (스크립트 인젝션). (CWE-78)
- 워크플로 `permissions`는 필요한 최소한만 준다.

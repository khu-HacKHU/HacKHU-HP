# 1 배경

본 문서는 갤러리 백엔드가 왜 필요한지와 이 세트에서 쓰는 용어를 정한다. 기능 범위와 완료 조건은 [BACKGROUND.md](../BACKGROUND.md)와 [USER-STORIES.md](../USER-STORIES.md)를 따른다.

<br>

### 1. 왜 필요한가

갤러리는 로그인 여부와 관계없이 누구나 보는 공개 콘텐츠다. 반면 올리기는 동아리원만 할 수 있어, 같은 기능 안에서 공개 조회와 인증된 쓰기가 섞인다. 사진 바이트는 백엔드가 받지 않고 S3에 직접 올라가므로, 백엔드는 **업로드·다운로드 주소를 발급하고 그 결과를 메타데이터로 저장·조회하는 역할**만 한다.

업로드 주소 발급 방식은 자료게시판 첨부파일([board](../../board/BACKGROUND.md))도 그대로 쓴다. 공유되는 부분은 `global/storage`에 두고, 이 문서는 갤러리가 그 공유 기능을 어떻게 쓰는지만 다룬다.

<br>

### 2. 관련 정책

- [D7](../../DECISIONS.md): 갤러리는 공개, 수정·삭제는 작성자와 관리자만.
- [D8](../../DECISIONS.md): jpg, png, webp만, 장당 10MB. SVG·zip 계열은 받지 않는다 (CWE-434).
- [D9](../../DECISIONS.md): 앨범 단위 업로드, 1장 이상 20장 이하, 수정 없음(지우고 재업로드).
- 탈퇴한 사용자가 올린 앨범은 데이터를 지우지 않고 남긴다. 다만 갤러리 API는 작성자 정보를 응답에 노출하지 않으므로 "탈퇴한 회원" 표시 로직([auth USER-STORIES 5절](../../auth/USER-STORIES.md))은 갤러리에는 적용되지 않는다. 삭제 권한 검사(#59)는 `uploader_id` 숫자 비교만으로 충분하다.

<br>

### 3. 용어

| 용어 | 뜻 |
|---|---|
| 앨범 | 제목, 활동 날짜, 사진 1~20장을 묶은 갤러리 게시 단위 |
| 대표 사진 | 앨범의 첫 번째 사진. 목록에서 앨범을 대표해 보여 줌 |
| 업로드 주소 | 클라이언트가 S3에 사진을 직접 올리기 위해 서버가 발급하는 presigned PUT URL |
| 조회 주소 | 사진을 보여주기 위해 클라이언트가 받는 사진의 접근 주소. **CDN(CloudFront) 서명 URL로 결정**. 갤러리는 공개 콘텐츠지만, 루트 `AGENTS.md`의 "파일은 presigned URL로만 주고받는다" 규칙을 지키려고 조회에도 서명을 건다 |
| 객체 키 | S3에 저장된 사진 파일의 경로. 형식 `{용도}/{uuid}.{확장자}`. 확장자는 발급 시점의 신고값이 아니라 매직바이트 검증으로 확인된 실제 형식 기준이다. 서버가 생성하고 사용자가 올린 파일명을 쓰지 않음 ([secure-coding.md 5절](../../../security/secure-coding.md)) |
| 업로드 발급 기록 | 업로드 주소를 발급할 때마다 `global/storage`(PL 소유, 게시판과 공유)에 남기는 기록(`uploadId`, 발급받은 사용자, 용도, 상태, 만료시간). 클라이언트는 객체 키를 직접 다루지 않고 `uploadId`만 주고받는다. 남의 객체 키를 가져다 쓰는 걸 막기 위함이다 |

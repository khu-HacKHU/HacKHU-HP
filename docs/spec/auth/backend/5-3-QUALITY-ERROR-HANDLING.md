# 5-3 오류 처리

<!-- 정하는 것: 이 기능의 에러 코드와 상태, 실패별 처리. 오류 처리는 여기 한곳에 모은다 -->

본 문서는 인증권한 API의 에러 코드와 상태, 실패별 처리를 정한다. 응답 형식은 API 규약을 따른다. ([api.md](../../../conventions/api.md))

지금은 가입(5-3-2), 로그인(5-3-3), refresh와 로그아웃(5-3-4), 요청마다 하는 인증(5-3-5), 요청 횟수 제한(5-3-6)을 정했다. 다른 API의 에러 코드는 각 구현 이슈에서 채운다.

<br>

### 5-3-1. 공통

- 인증권한팀이 만드는 에러 코드는 `AUTH_` 접두사를 붙인다. 코드는 `domain/user/exception/UserErrorCode`, `domain/auth/exception/AuthErrorCode`에 둔다. Security 필터가 직접 주는 코드는 필터가 도메인 패키지에 기대지 않게 `global/security/SecurityErrorCode`에 둔다.
- 도메인에 속하지 않는 실패는 공통 코드를 쓴다. 401 `UNAUTHORIZED`, 403 `FORBIDDEN`, 400 `INVALID_INPUT`, 415 `UNSUPPORTED_MEDIA_TYPE`, 429 `TOO_MANY_REQUESTS`가 여기에 든다.
- 입력 검증 실패는 400 `INVALID_INPUT`이고 `errors`에 칸별 사유를 담는다. 한 칸에 사유가 여럿일 수 있다. 프론트엔드는 `field`로 칸을 찾아 `reason`을 보여 준다.
- 에러 응답에 입력한 이메일, 이름, 비밀번호를 다시 싣지 않는다. 사유 문구는 고정 문장이다.

<br>

### 5-3-2. 가입

| 실패 | 상태 | 코드 | 처리 |
|---|---|---|---|
| 필수 항목이 비었거나 규칙에 맞지 않음 | 400 | `INVALID_INPUT` | 칸별 사유를 `errors`에 담음 <br> 행을 만들지 않음 |
| 본문이 JSON이 아니거나 깨짐 | 415, 400 | `UNSUPPORTED_MEDIA_TYPE`, `INVALID_INPUT` | 행을 만들지 않음 |
| 활성 계정이 이미 쓰는 이메일 | 409 | `AUTH_DUPLICATE_EMAIL` | 대소문자만 달라도 같은 이메일로 봄 <br> bcrypt를 계산하기 전에 끝냄 |
| 확인과 저장 사이에 같은 이메일이 먼저 저장됨 | 409 | `AUTH_DUPLICATE_EMAIL` | `uk_users_email` 위반을 바꿈 (5-2) |
| 그 밖의 DB 제약 위반 | 500 | `INTERNAL_ERROR` | 409로 바꾸지 않음 <br> 검증이 빠뜨린 버그이므로 서버 로그에 ERROR로 남김 |

**칸별 사유**

| 칸 | 조건 | 사유 |
|---|---|---|
| email | 비었음 | 이메일을 입력해주세요. |
| email | 254자 초과 | 이메일은 254자 이하로 입력해주세요. |
| email | ASCII가 아닌 문자나 공백이 있음 | 이메일은 영문, 숫자, 기호로만 입력해주세요. |
| email | 이메일 형식이 아님 | 이메일 형식이 올바르지 않습니다. |
| password | 비었음 | 비밀번호를 입력해주세요. |
| password | 10자 미만이거나 64자 초과 | 비밀번호는 10자 이상 64자 이하로 입력해주세요. |
| password | UTF-8로 72바이트 초과 | 비밀번호가 너무 깁니다. 한글이나 기호가 많으면 64자보다 짧아도 길이 제한을 넘을 수 있습니다. |
| password | 이메일과 같음 (대소문자 무시) | 비밀번호는 이메일과 다르게 입력해주세요. |
| name | 비었음 | 이름을 입력해주세요. |
| name | 30자 초과 | 이름은 30자 이하로 입력해주세요. |
| name | 제어 문자나 양방향 텍스트 제어 문자가 있음 | 이름에 쓸 수 없는 문자가 있습니다. |

- 글자 수는 코드 포인트로 센다. 이모지 하나가 1자다.
- 409는 그 이메일이 가입되어 있다는 것을 드러낸다. 사용자 스토리가 요구하므로 받아들인다. (5-1-QUALITY-SECURITY.md 5-1-11)

<br>

### 5-3-3. 로그인

| 실패 | 상태 | 코드 | 처리 |
|---|---|---|---|
| `Origin`이 없거나 허용 목록에 없음 | 403 | `FORBIDDEN` | 컨트롤러에 닿기 전에 끝남 <br> 세션과 쿠키를 건드리지 않음 <br> 로그를 남기지 않음 |
| 본문이 JSON이 아님 | 415 | `UNSUPPORTED_MEDIA_TYPE` | 세션을 만들지 않음 |
| 이메일이나 비밀번호가 비었음 | 400 | `INVALID_INPUT` | `errors`에 칸별 사유 <br> 요청 횟수 제한에 세지 않음 |
| 요청 횟수 제한 | 429 | `TOO_MANY_REQUESTS` | 5-3-6 <br> 비밀번호를 확인하지 않음 |
| 이메일이 없음, 비밀번호가 틀림, 탈퇴한 계정, 임시 비밀번호가 만료되었거나 이미 쓰임, 검증 직후 비밀번호가 바뀌거나 탈퇴함 | 401 | `AUTH_INVALID_CREDENTIALS` | 모두 같은 응답 <br> IP와 사용자 ID(계정이 있을 때)를 INFO 로그로 남김 <br> 입력한 이메일은 남기지 않음 <br> 요청에 실려 온 기존 세션을 건드리지 않음 |
| 비밀번호가 UTF-8로 72바이트를 넘음 | 401 | `AUTH_INVALID_CREDENTIALS` | 가입 규칙상 저장될 수 없는 값이라 틀린 비밀번호로 봄 <br> 500이 아님 |

**칸별 사유**

| 칸 | 조건 | 사유 |
|---|---|---|
| email | 비었음 | 이메일을 입력해주세요. |
| password | 비었음 | 비밀번호를 입력해주세요. |

`AUTH_INVALID_CREDENTIALS`의 메시지는 "이메일 또는 비밀번호가 올바르지 않습니다."다. 어느 쪽이 틀렸는지 알려 주지 않는다. ([DECISIONS.md](DECISIONS.md) A24)

### 5-3-4. refresh와 로그아웃

| API | 실패 | 상태 | 코드 | 처리 |
|---|---|---|---|---|
| refresh, 로그아웃 | `Origin`이 없거나 허용 목록에 없음 | 403 | `FORBIDDEN` | 회전, 폐기를 하지 않음 |
| refresh | 쿠키가 없음, 모르는 토큰, 만료된 토큰, 폐기되었거나 30일이 지난 세션, 탈퇴했거나 거절된 계정 | 401 | `UNAUTHORIZED` | 쿠키를 지움 |
| refresh | 재사용 (4-2-5의 네 번째 줄) | 401 | `UNAUTHORIZED` | 세션을 `REUSE_DETECTED`로 폐기하고 커밋함 <br> 사용자 ID, 세션 ID, IP를 WARN 로그로 남김 <br> 쿠키를 지움 |
| 로그아웃 | 쿠키가 없음, 모르는 토큰, 이미 폐기된 세션 | 204 | | 실패로 보지 않음 <br> 쿠키를 지움 |

<br>

### 5-3-5. 요청마다 하는 인증

access 토큰 검증 필터가 컨트롤러에 닿기 전에 준다. ([5-1-QUALITY-SECURITY.md](5-1-QUALITY-SECURITY.md) 5-1-4)

| 실패 | 상태 | 코드 | 처리 |
|---|---|---|---|
| `Authorization`이 `Bearer`가 아님, 토큰이 비었음, 서명이 틀림, `HS256`이 아님, 발급자가 다름, 만료됨, 세션이 없거나 폐기되었거나 만료됨, 세션의 사용자가 `sub`와 다름, 탈퇴한 계정 | 401 | `UNAUTHORIZED` | 모두 같은 응답 (A14) <br> 이유는 DEBUG 로그에만 남김 <br> 공개 API여도 401 |
| 비밀번호 변경 필요 상태에서 내 정보 조회, 비밀번호 변경이 아닌 API를 부름 | 403 | `AUTH_PASSWORD_CHANGE_REQUIRED` | 사용자 ID, 메서드, 경로를 INFO 로그로 남김 |

`AUTH_PASSWORD_CHANGE_REQUIRED`의 메시지는 "비밀번호를 변경한 뒤 이용할 수 있습니다."다.

<br>

### 5-3-6. 요청 횟수 제한

| 실패 | 상태 | 코드 | 처리 |
|---|---|---|---|
| 로그인, 가입, 비밀번호 변경과 탈퇴의 한도를 넘음 | 429 | `TOO_MANY_REQUESTS` | `Retry-After`에 창이 끝날 때까지 남은 초(올림) <br> IP를 INFO 로그로 남김 <br> 로그는 창마다 처음 거부할 때만 남김 |

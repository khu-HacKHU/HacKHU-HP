# 5-3 오류 처리

<!-- 정하는 것: 이 기능의 에러 코드와 상태, 실패별 처리. 오류 처리는 여기 한곳에 모은다 -->

본 문서는 인증권한 API의 에러 코드와 상태, 실패별 처리를 정한다. 응답 형식은 API 규약을 따른다. ([api.md](../../../conventions/api.md))

지금은 가입(5-3-2)만 정했다. 다른 API의 에러 코드는 각 구현 이슈에서 채운다.

<br>

### 5-3-1. 공통

- 인증권한팀이 만드는 에러 코드는 `AUTH_` 접두사를 붙인다. 코드는 `domain/user/exception/UserErrorCode`, `domain/auth/exception/AuthErrorCode`에 둔다.
- 도메인에 속하지 않는 실패는 공통 코드를 쓴다. 401 `UNAUTHORIZED`, 403 `FORBIDDEN`, 400 `INVALID_INPUT`, 415 `UNSUPPORTED_MEDIA_TYPE`, 429 `TOO_MANY_REQUESTS`가 여기에 든다.
- 입력 검증 실패는 400 `INVALID_INPUT`이고 `errors`에 칸별 사유를 담는다. 한 칸에 사유가 여럿일 수 있다. 프론트엔드는 `field`로 칸을 찾아 `reason`을 보여 준다.
- 에러 응답에 입력한 이메일, 이름, 비밀번호를 다시 싣지 않는다. 사유 문구는 고정 문장이다.

<br>

### 5-3-2. 가입

| 실패 | 상태 | 코드 | 처리 |
|---|---|---|---|
| 필수 항목이 비었거나 규칙에 맞지 않음 | 400 | `INVALID_INPUT` | 칸별 사유를 `errors`에 담음 <br> 행을 만들지 않음 |
| 본문이 JSON이 아니거나 깨짐 | 415, 400 | `UNSUPPORTED_MEDIA_TYPE`, `INVALID_INPUT` | 행을 만들지 않음 |
| 활성 계정이 이미 쓰는 이메일 | 409 | `AUTH_DUPLICATE_EMAIL` | 대소문자만 달라도 같은 이메일로 봄 <br> bcrypt를 계산하기 전에 끝냄 |
| 확인과 저장 사이에 같은 이메일이 먼저 저장됨 | 409 | `AUTH_DUPLICATE_EMAIL` | `uk_users_email` 위반을 바꿈 (5-2) |
| 그 밖의 DB 제약 위반 | 500 | `INTERNAL_ERROR` | 409로 바꾸지 않음 <br> 검증이 빠뜨린 버그이므로 서버 로그에 ERROR로 남김 |

**칸별 사유**

| 칸 | 조건 | 사유 |
|---|---|---|
| email | 비었음 | 이메일을 입력해주세요. |
| email | 254자 초과 | 이메일은 254자 이하로 입력해주세요. |
| email | ASCII가 아닌 문자나 공백이 있음 | 이메일은 영문, 숫자, 기호로만 입력해주세요. |
| email | 이메일 형식이 아님 | 이메일 형식이 올바르지 않습니다. |
| password | 비었음 | 비밀번호를 입력해주세요. |
| password | 10자 미만이거나 64자 초과 | 비밀번호는 10자 이상 64자 이하로 입력해주세요. |
| password | UTF-8로 72바이트 초과 | 비밀번호가 너무 깁니다. 한글이나 기호가 많으면 64자보다 짧아도 길이 제한을 넘을 수 있습니다. |
| password | 이메일과 같음 (대소문자 무시) | 비밀번호는 이메일과 다르게 입력해주세요. |
| name | 비었음 | 이름을 입력해주세요. |
| name | 30자 초과 | 이름은 30자 이하로 입력해주세요. |
| name | 제어 문자나 양방향 텍스트 제어 문자가 있음 | 이름에 쓸 수 없는 문자가 있습니다. |

- 글자 수는 코드 포인트로 센다. 이모지 하나가 1자다.
- 409는 그 이메일이 가입되어 있다는 것을 드러낸다. 사용자 스토리가 요구하므로 받아들인다. (5-1-QUALITY-SECURITY.md 5-1-11)

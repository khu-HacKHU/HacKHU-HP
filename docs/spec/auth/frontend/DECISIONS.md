# 인증권한 프론트엔드 결정 기록

결정 시점의 기록이다. 쓴 뒤 고치지 않고, 결정이 바뀌면 새 줄을 덧붙이고 옛 줄의 상태만 바꾼다.

| 결정 | 날짜 | 상태 | 배경 | 채택 | 대안 | 영향 |
|---|---|---|---|---|---|---|
| AF1. access 토큰을 모듈 변수 하나에 둔다 | 2026-11-19 | 채택 | 계약(4-2-1)이 "메모리에만 둔다"까지 정하고 보관 방법은 프론트엔드 세트에 넘겼다. 요청 공통 처리는 컴포넌트 밖에서 토큰을 읽고 갱신해야 한다. | `features/auth/session.ts`의 모듈 변수에 두고 구독으로 화면에 잇는다(`useSyncExternalStore`). React 상태에 직접 두지 않는다. | React Context에만 두는 안. 컴포넌트 밖의 `lib/api.ts`가 토큰을 읽을 수 없어 호출마다 토큰을 인자로 넘겨야 한다. 그러면 빠뜨리기 쉽다. | 토큰을 읽고 쓰는 곳이 한 파일로 모인다. 새로고침하면 사라져 복구가 필요하다(4-2-2). |
| AF2. 새로고침 복구를 앱이 시작할 때 refresh 한 번으로 한다 | 2026-11-19 | 채택 | access 토큰이 메모리에만 있어 새로고침하면 사라진다. 로그인 상태가 유지되어 보여야 한다. | 앱이 시작할 때 `POST /api/v1/auth/refresh`를 한 번 부른다. 응답에 `user`가 함께 와서 요청 한 번으로 끝난다. 끝날 때까지 로그인 여부를 단정하지 않는다. | 내 정보 API를 함께 부르는 안. 요청이 두 번이고 refresh 응답에 이미 `user`가 있어 필요 없다. 복구 중에 로그인 버튼을 먼저 보여 주는 안. 로그인한 사용자가 새로고침할 때마다 버튼이 깜빡인다. | 로그인하지 않은 방문자도 첫 화면에서 refresh를 한 번 부른다. 401이 정상 경로라 오류로 다루지 않는다. |
| AF3. 갱신 요청을 한 번에 하나만 보낸다 | 2026-11-19 | 채택 | 화면 하나가 여러 요청을 동시에 보내면 만료된 토큰으로 여러 401이 동시에 온다. | 진행 중인 갱신 Promise를 모듈에 두고 뒤이은 요청은 그것을 기다린다. 끝나면 비운다. | 요청마다 갱신하는 안. 갱신이 refresh 토큰을 회전시키므로 뒤에 도착한 것이 재사용으로 판정되어 세션 전체가 끊긴다(4-2-5). | 갱신 중에 들어온 요청은 조금 기다린다. |

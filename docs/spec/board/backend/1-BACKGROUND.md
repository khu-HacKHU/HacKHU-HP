# 1 배경

본 문서는 게시판 기능에 어떤 백엔드가 왜 필요한지와 이 세트에서 쓰는 용어를 정한다. 기능 범위와 완료 조건은 배경과 사용자 스토리를 따른다. ([BACKGROUND.md](../BACKGROUND.md), [USER-STORIES.md](../USER-STORIES.md))

이번 판은 공지만 다룬다. 자유게시판, 자료게시판과 첨부파일은 #31에서 덧붙인다.

<br>

### 1-1. 왜 필요한가

공지는 운영진이 동아리 소식을 동아리원과 외부 방문자에게 알리는 창구다. 읽기는 누구나 하고, 쓰기는 운영진만 한다. 그래서 같은 기능 안에 공개 조회와 역할이 필요한 쓰기가 섞인다.

게시판 백엔드는 아래를 맡는다.

- 공지의 제목, 본문, 작성자, 작성 시각을 저장한다.
- 로그인하지 않은 사람에게도 공지 목록과 글을 준다.
- 공지를 쓰려는 사람이 운영진인지, 고치거나 지우려는 사람이 작성자나 관리자인지 서버에서 확인한다. 화면에서 버튼을 숨기는 것만으로는 막지 못한다. ([secure-coding.md](../../../security/secure-coding.md))

현재 사용자와 역할은 인증권한팀이 제공하는 방법으로 얻는다. ([auth 3-1](../../auth/backend/3-1-DESIGN-SOFTWARE-ARCHITECTURE.md))

<br>

### 1-2. 관련 정책

| 정책 | 이 세트에 주는 영향 |
|---|---|
| 공지는 공개, 수정과 삭제는 작성자와 관리자 (D7) | 목록과 상세는 인증 없이 열고, 수정과 삭제는 글마다 작성자를 확인함 |
| 역할 5단계와 상속 (D6, PRODUCT.md 4절) | 공지 쓰기는 운영진과 관리자가 통과함 <br> 승인 대기 회원은 방문자와 같이 다룸 |
| 본문은 글자만 씀 (BACKGROUND.md 2절) | 본문을 꾸밈 없는 글자로 저장하고 HTML로 해석하지 않음 <br> 줄바꿈은 쓴 그대로 저장함 |
| 댓글과 검색은 첫 버전에 없음 (PRODUCT.md 3절) | 댓글 테이블과 검색 API를 만들지 않음 |
| 목록은 최신 글부터 한 페이지 20개 (USER-STORIES.md 1절) | 정렬은 서버가 고정함 <br> 페이지 크기는 기본 20, 최대 20 |
| 메인 화면에 최근 공지 5개 (홈 USER-STORIES.md 1절, PR #102) | 갤러리팀이 만드는 메인 화면이 공지 목록 API를 페이지 크기 5로 부름 |
| 탈퇴해도 글은 남김 (auth USER-STORIES.md 5절) | 작성자 행을 지우지 않으므로 글도 지우지 않음 <br> 작성자 이름 대신 "탈퇴한 회원"으로 보여 줌 |

결정 번호는 제품 결정 기록을 따른다. ([DECISIONS.md](../../DECISIONS.md)) 이 세트의 기술 결정은 세트 결정 기록에 있다. ([DECISIONS.md](DECISIONS.md))

<br>

### 1-3. 용어

| 용어 | 뜻 |
|---|---|
| 글 | 게시판에 올린 제목과 본문 한 묶음 <br> 세 게시판이 같은 구조를 씀 |
| 게시판 종류 | 글이 속한 게시판을 나타내는 저장 값 <br> 이번 판에서는 `NOTICE`(공지)만 있음 <br> 자유게시판과 자료게시판 값은 #31에서 더함 |
| 공지 | 게시판 종류가 `NOTICE`인 글 |
| 작성자 | 글을 처음 쓴 사람 <br> 수정해도 바뀌지 않음 |
| 역할 코드 | 인증권한 세트의 정의를 따름 <br> `PENDING`, `MEMBER`, `STAFF`, `ADMIN` ([auth 1-3](../../auth/backend/1-BACKGROUND.md)) |
| 탈퇴한 작성자 | 인증권한 세트에서 익명화된 계정이 쓴 글의 작성자 |

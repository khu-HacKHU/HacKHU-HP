# 1 배경

본 문서는 게시판 기능에 어떤 백엔드가 왜 필요한지와 이 세트에서 쓰는 용어를 정한다. 기능 범위와 완료 조건은 배경과 사용자 스토리를 따른다. ([BACKGROUND.md](../BACKGROUND.md), [USER-STORIES.md](../USER-STORIES.md))

<br>

### 1-1. 왜 필요한가

게시판은 성격이 다른 세 가지로 나뉜다. 그래서 같은 기능 안에 공개 조회, 동아리원 전용 조회, 역할이 필요한 쓰기, 파일 업로드가 함께 있다.

| 게시판 | 읽기 | 쓰기 | 백엔드가 특히 막아야 하는 것 |
|---|---|---|---|
| 공지 | 누구나 | 운영진 | 운영진이 아닌 사람의 쓰기 |
| 자유게시판 | 동아리원 | 동아리원 | 방문자와 승인 대기 회원의 읽기 |
| 자료게시판 | 동아리원 | 동아리원 | 방문자와 승인 대기 회원의 읽기, 위험한 파일 업로드, 다운로드 링크의 오래 쓰기 |

게시판 백엔드는 아래를 맡는다.

- 글의 제목, 본문, 작성자, 작성 시각을 저장한다.
- 공지는 로그인하지 않은 사람에게도 목록과 글을 준다. 자유게시판과 자료게시판은 동아리원에게만 준다.
- 쓰려는 사람의 역할과, 고치거나 지우려는 사람이 작성자나 관리자인지 서버에서 확인한다. 화면에서 버튼을 숨기는 것만으로는 막지 못한다. ([secure-coding.md](../../../security/secure-coding.md))
- 자료게시판 첨부파일의 업로드 주소와 다운로드 주소를 발급하고, 올라온 파일이 허용한 형식인지 확인한다. 파일 바이트는 서버를 거치지 않고 S3에 직접 오간다. ([secure-coding.md](../../../security/secure-coding.md) 5절)

현재 사용자와 역할은 인증권한팀이 제공하는 방법으로 얻는다. ([auth 3-1](../../auth/backend/3-1-DESIGN-SOFTWARE-ARCHITECTURE.md)) 업로드 주소 발급과 발급 기록은 갤러리팀이 만드는 공유 기능(`global/storage`)을 쓴다. ([gallery 1-BACKGROUND](../../gallery/backend/1-BACKGROUND.md))

<br>

### 1-2. 관련 정책

| 정책 | 이 세트에 주는 영향 |
|---|---|
| 공지는 공개, 자유게시판과 자료게시판은 동아리원만, 수정과 삭제는 작성자와 관리자 (D7) | 공지 목록과 상세만 인증 없이 열고, 나머지는 동아리원 수준을 먼저 확인함 <br> 수정과 삭제는 글마다 작성자를 확인함 |
| 역할 5단계와 상속 (D6, PRODUCT.md 4절) | 공지 쓰기는 운영진과 관리자가 통과함 <br> 승인 대기 회원은 방문자와 같이 다룸 |
| 업로드 파일의 형식과 크기 제한 (D8) | 자료 첨부는 pdf, docx, pptx, xlsx, 파일 하나 20MB, 글 하나에 5개 <br> 파일 구조를 어디까지 확인할지는 이 세트가 정함 (5-1-7) |
| 파일은 presigned URL로만 주고받음 (루트 AGENTS.md, secure-coding.md 5절) | 서버는 파일 바이트를 받지 않고 업로드, 다운로드 주소만 발급함 |
| 다운로드 링크는 받은 지 10분이 지나면 열리지 않음 (USER-STORIES.md 4절) | 다운로드 주소의 만료를 10분으로 둠 |
| 본문은 글자만 씀 (BACKGROUND.md 2절) | 본문을 꾸밈 없는 글자로 저장하고 HTML로 해석하지 않음 <br> 줄바꿈은 쓴 그대로 저장함 |
| 댓글과 검색은 첫 버전에 없음 (PRODUCT.md 3절) | 댓글 테이블과 검색 API를 만들지 않음 |
| 목록은 최신 글부터 한 페이지 20개 (USER-STORIES.md 1절) | 정렬은 서버가 고정함 <br> 페이지 크기는 기본 20, 최대 20 |
| 메인 화면에 최근 공지 5개 (홈 USER-STORIES.md 1절, PR #102) | 갤러리팀이 만드는 메인 화면이 공지 목록 API를 페이지 크기 5로 부름 <br> 자유게시판과 자료게시판 글은 메인 화면에 보이지 않음 |
| 탈퇴해도 글은 남김 (auth USER-STORIES.md 5절) | 작성자 행을 지우지 않으므로 글과 첨부파일도 지우지 않음 <br> 작성자 이름 대신 "탈퇴한 회원"으로 보여 줌 |

결정 번호는 제품 결정 기록을 따른다. ([DECISIONS.md](../../DECISIONS.md)) 이 세트의 기술 결정은 세트 결정 기록에 있다. ([DECISIONS.md](DECISIONS.md))

<br>

### 1-3. 용어

| 용어 | 뜻 |
|---|---|
| 글 | 게시판에 올린 제목과 본문 한 묶음 <br> 세 게시판이 같은 구조를 씀 |
| 게시판 종류 | 글이 속한 게시판을 나타내는 저장 값 <br> `NOTICE`(공지), `FREE`(자유게시판), `ARCHIVE`(자료게시판) |
| 공지, 자유게시판 글, 자료게시판 글 | 게시판 종류가 각각 `NOTICE`, `FREE`, `ARCHIVE`인 글 |
| 작성자 | 글을 처음 쓴 사람 <br> 수정해도 바뀌지 않음 |
| 첨부파일 | 자료게시판 글에 붙은 파일 <br> 다른 게시판 글에는 붙지 않음 |
| 업로드 주소 | 클라이언트가 S3에 파일을 직접 올리도록 서버가 발급하는 presigned PUT URL |
| 업로드 발급 기록 | 업로드 주소를 발급할 때 `global/storage`에 남기는 기록 <br> 클라이언트는 객체 키 대신 기록의 ID(`uploadId`)만 주고받음 ([gallery 1-BACKGROUND](../../gallery/backend/1-BACKGROUND.md)) |
| 다운로드 주소 | 첨부파일을 받도록 서버가 발급하는 presigned GET URL <br> 10분 뒤 만료됨 |
| 객체 키 | S3에 저장된 파일의 경로 <br> 서버가 만들고 사용자가 올린 파일 이름을 쓰지 않음 |
| 원래 파일 이름 | 사용자가 올린 파일의 이름 <br> 화면 표시와 내려받을 때의 이름에만 쓰고 객체 키에 쓰지 않음 |
| 역할 코드 | 인증권한 세트의 정의를 따름 <br> `PENDING`, `MEMBER`, `STAFF`, `ADMIN` ([auth 1-3](../../auth/backend/1-BACKGROUND.md)) |
| 탈퇴한 작성자 | 인증권한 세트에서 익명화된 계정이 쓴 글의 작성자 |

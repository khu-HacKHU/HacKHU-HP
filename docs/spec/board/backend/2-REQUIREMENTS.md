# 2 요구사항

본 문서는 프론트엔드가 게시판 백엔드에 기대하는 것을 측정할 수 있는 값으로 정한다. 이번 판은 공지만 다룬다.

<br>

### 2-1. 글의 길이

| 항목 | 값 |
|---|---|
| 제목 | 앞뒤 공백을 지운 뒤 1자 이상 100자 이하 |
| 본문 | 1자 이상 10,000자 이하 <br> 공백과 줄바꿈만으로 된 본문은 받지 않음 |

- 사용자 스토리가 길이 제한을 게시판팀에 맡겼다. (USER-STORIES.md 1절)
- 글자 수는 유니코드 코드 포인트 단위로 센다. 한글 한 자와 영문 한 자를 같은 한 자로 센다.
- 10,000자는 A4 약 5장 분량이다. 공지는 이보다 길 필요가 없다고 본다. 운영 중에 모자라면 늘린다.
- 이 값은 세 게시판이 함께 쓴다. 자유게시판과 자료게시판에서 다른 값이 필요하면 #31에서 정한다.

<br>

### 2-2. 목록

| 항목 | 값 |
|---|---|
| 정렬 | 작성 시각이 최신인 글부터 <br> 작성 시각이 같으면 ID가 큰 글부터 |
| 페이지 크기 | 기본 20개 <br> 1개부터 20개까지 요청할 수 있음 <br> 20개를 넘게 요청하면 20개로 맞춤 |
| 페이지 번호 | 0부터 |
| 목록에 주는 것 | 제목, 작성자, 작성 시각, 수정 시각 <br> 본문은 주지 않음 |

- 게시판 목록 화면은 사용자 스토리대로 한 페이지에 20개를 보여 준다. (USER-STORIES.md 1절)
- 메인 화면은 최신 공지 5개만 보여 준다. 그래서 페이지 크기를 줄여 요청할 수 있게 한다. 메인 화면은 갤러리팀이 만들고 이 목록 API를 쓴다. (홈 USER-STORIES.md 1절, 제품 DECISIONS.md D12, PR #102)
- 정렬은 클라이언트가 바꿀 수 없다. 최신순이 아닌 정렬을 요청하면 거부한다. ([4-2-INTERACTION-CONTRACT.md](4-2-INTERACTION-CONTRACT.md))
- 마지막 페이지를 넘는 번호를 요청하면 빈 목록을 준다. 오류로 다루지 않는다.

<br>

### 2-3. 응답 시간

| API | 목표 (p95) |
|---|---|
| 공지 목록 | 300ms 이하 |
| 공지 상세 | 300ms 이하 |
| 공지 작성, 수정, 삭제 | 300ms 이하 <br> 인증 처리 20ms 포함 ([auth 2-3](../../auth/backend/2-REQUIREMENTS.md)) |

동아리 규모(가입자 수백 명, 공지 수백 건)를 가정한다. 별도 성능 테스트는 두지 않는다.

<br>

### 2-4. 처리량과 요청 제한

동시 사용자가 적어 처리량 목표는 두지 않는다. 공지 쓰기는 운영진만 할 수 있어 요청 횟수 제한을 두지 않는다. 공개 조회 API의 대량 요청 대응은 보안 문서에서 다룬다. ([5-1-QUALITY-SECURITY.md](5-1-QUALITY-SECURITY.md))

<br>

### 2-5. 반영 시점

| 변경 | 반영 시점 |
|---|---|
| 공지 작성, 수정 | 성공 응답을 받은 뒤의 다음 조회부터 |
| 공지 삭제 | 성공 응답을 받은 뒤의 다음 조회부터 404 |
| 작성자의 역할 변경, 탈퇴 | 다음 요청부터 ([auth 2-2](../../auth/backend/2-REQUIREMENTS.md)) |

공지 응답에는 서버 캐시를 두지 않는다.

<br>

### 2-6. 보존 기간과 데이터 수명

| 데이터 | 수명 |
|---|---|
| 공지 | 작성자나 관리자가 지울 때까지 <br> 자동으로 지우지 않음 |
| 지운 공지 | 삭제 즉시 행을 지움 <br> 복구하지 않음 |
| 탈퇴한 작성자의 공지 | 지우지 않고 남김 <br> 작성자는 "탈퇴한 회원"으로 보여 줌 |
